## Dimension 1 — Accessibility · 2/4 (unchanged)

**Fixed since last audit:**
- `contas.tsx:317` — native `<input type="checkbox">` replaced with `<Checkbox id={...}>` + matching `<Label htmlFor>` — now correctly paired.

**Still open — the dominant issue:**
- **Label/input association is systemic, not isolated.** `<Label>Texto</Label>` is written as a plain sibling of `<Input>`/`<Select>` with no `htmlFor`/`id` pair in **127 occurrences across 35 route files** (verified via grep for the sibling pattern; confirmed by direct read of `auth.tsx:96-175`, `tesouraria/contas.tsx:87-115`, and others). Only 3 files (`form.tsx`, `tesouraria/contas.tsx` Pix block, `tesouraria/index.tsx` partially) pair correctly. Because Radix `Label` only auto-associates when the control is nested inside it, every one of these 127 labels is visual-only: a screen reader tabbing into the field announces no accessible name, and clicking the label text does not focus the input.
- `tesouraria/contas.tsx:146-157` — icon-only expand/collapse `<Button variant="ghost">` (ChevronDown/ChevronRight) still has no `aria-label`.
- `tesouraria/conciliacao.tsx:197,232` — OFX/system list row selection is communicated only via a `bg-muted` class swap; no `aria-pressed`/`aria-selected` on the selectable `<button>`.
- No `aria-live`/`aria-busy` region for query loading states outside of Sonner toasts (unchanged from prior audit).

**Score 0-4**: 2=Partial (some a11y effort — sidebar contrast fixed, icon-nav buttons carry `aria-label`, tooltips present — but a form-heavy financial/admin system with unlabeled inputs on 35 pages is a significant, user-facing gap).

## Detailed Findings by Severity

**[P1] Systemic unlabeled form fields**
- **Location:** 35 files, 127 occurrences — representative: `auth.tsx:96-175`, `tesouraria/contas.tsx:87-115`, `orgs/index.tsx` (11), `tesouraria/faturas/index.tsx` (17), `tesouraria/tabela-valores.tsx` (12)
- **Category:** Accessibility
- **Impact:** Screen reader users get no accessible name when they tab into these inputs; sighted mouse users lose the "click label to focus field" affordance. This is the app's primary data-entry pattern across nearly every admin/finance form.
- **WCAG/Standard:** 1.3.1 Info and Relationships (A), 4.1.2 Name, Role, Value (A)
- **Recommendation:** Add matching `id`/`htmlFor` to every `<Label>`+`<Input>`/`<Select>`/`<Textarea>` pair, or switch these forms onto the existing `components/ui/form.tsx` (`FormLabel`/`FormField`) pattern already used correctly elsewhere, which associates automatically.
- **Suggested command:** `/impeccable harden`

**[P1] Dashboard queries render silently on fetch failure**
- **Location:** `dashboard.tsx` (6 `useQuery` calls), `painel/index.tsx:75` (`isLoading`-only check)
- **Category:** Implementation Integrity
- **Impact:** A failed request looks identical to "no data yet" — user sees an empty dashboard with no indication anything is wrong, and no way to retry short of a full page reload.
- **WCAG/Standard:** —
- **Recommendation:** Reuse the `isError` + "Tentar novamente" pattern already implemented at `tesouraria/index.tsx:231-241`.
- **Suggested command:** `/impeccable harden`

**[P2] Financial data fully hidden (not reflowed) on mobile**
- **Location:** `tesouraria/index.tsx:189-259` — Emissão and Categoria columns
- **Category:** Responsive Design
- **Impact:** Users on phones cannot see when a lançamento was issued or its category at all — not degraded, absent — with no expandable row or detail view to recover it.
- **WCAG/Standard:** 1.4.10 Reflow (AA, informative — this is data loss, not just layout reflow)
- **Recommendation:** Add an expandable row (chevron → inline detail) or a compact secondary line under the primary cell showing the hidden fields on narrow viewports.
- **Suggested command:** `/impeccable adapt`

**[P2] Icon-only controls without accessible names**
- **Location:** `tesouraria/contas.tsx:146-157` (expand/collapse chevron button)
- **Category:** Accessibility
- **Impact:** Screen reader announces an unlabeled button with no indication of what it does or its current state.
- **WCAG/Standard:** 4.1.2 Name, Role, Value (A)
- **Recommendation:** Add `aria-label="Expandir chaves Pix"` / `"Recolher chaves Pix"` (toggle by `expandido === c.id`) and consider `aria-expanded`.
- **Suggested command:** `/impeccable harden`

**[P2] Selection state conveyed by color only**
- **Location:** `tesouraria/conciliacao.tsx:197,232`
- **Category:** Accessibility
- **Impact:** Selected OFX/system rows are indistinguishable to screen reader users and to anyone relying on non-color cues.
- **WCAG/Standard:** 1.4.1 Use of Color (A), 4.1.2 (A)
- **Recommendation:** Add `aria-pressed={selSistema === s.id}` (or `role="option"`/`aria-selected` if this is really a listbox) to the selectable buttons.
- **Suggested command:** `/impeccable clarify`

**[P3] Duplicate `MetricCard` component**
- **Location:** `painel/index.tsx:243`, `dashboard.tsx`
- **Category:** Implementation Integrity
- **Impact:** Two implementations of one visual pattern with a diverging API (`tone="gold"` only in one) — a future style change has to be made twice and can drift.
- **Recommendation:** Extract to `@/components/app/MetricCard.tsx`, add `tone="gold"` to the shared version.
- **Suggested command:** `/impeccable extract`

**[P3] Root metadata language mismatch**
- **Location:** `src/routes/__root.tsx:83-102`
- **Category:** Implementation Integrity
- **Impact:** `<html lang="pt-BR">` and every route's own title are Portuguese; the root `title`/`description`/OG/Twitter tags are English ("Fraternity Ledger"). Inconsistent for link previews and translation tools.
- **Recommendation:** Localize the root meta block to match the product's language (e.g. "Gestão da Loja" / a Portuguese description), or confirm this is intentional if the org wants an English-facing share preview.
- **Suggested command:** `/impeccable clarify`

**[P3] No route-level code splitting**
- **Location:** All 63 route files (`src/routes/`)
- **Category:** Performance
- **Impact:** None today (build is fast, bundle is modest); the risk grows every time a new route is added.
- **Recommendation:** Adopt `lazy()` route definitions for the heavier modules (`contabilidade/*`, `tesouraria/*`) before the bundle becomes a felt problem.
- **Suggested command:** `/impeccable optimize`

**[P3] Overused font: Inter**
- **Location:** `src/routes/__root.tsx:109`, `src/styles.css:65`
- **Category:** Implementation Integrity (detector, advisory)
- **Impact:** Purely aesthetic — Inter is the most common typeface in AI-generated UIs and reads as templated rather than distinctive, though it is legible and functionally fine.
- **Recommendation:** If a more distinctive institutional voice is wanted, consider a serif or slab display face for headings paired with Inter (or a replacement) for body text.
- **Suggested command:** `/impeccable typeset`

## Patterns & Systemic Issues

- **Label association is the single largest gap in the app**, not a one-off oversight: 127 instances across 35 files, all sharing the same fix. Everything else found is isolated to 1-2 files.
- **Error-state handling exists but hasn't propagated**: the correct `isError`/retry pattern was built once (`tesouraria/index.tsx`) but not carried to `painel/index.tsx` or `dashboard.tsx`, which share the same `useQuery` shape.

## Positive Findings

- Theming is a genuine standout: fully token-driven oklch system, deliberate light/dark parity, and a documented, intentional exception (brand-locked sidebar) rather than an oversight.
- The team has a track record of closing prior audit findings correctly and completely — the P0 valor guard, both Cancel buttons, and the tiles grid bug were all fixed exactly as recommended, with no regressions introduced elsewhere.
- Responsive touch-target sizing is thoughtfully tuned per input method (`h-10` mobile / `sm:h-9` desktop on buttons) rather than a single fixed size — deliberate craft, not an accident.
- Icon-only sidebar/header controls (`AppShell.tsx`) consistently carry `aria-label` + tooltip pairs; this pattern just hasn't been extended to the newer table-level icon buttons.
