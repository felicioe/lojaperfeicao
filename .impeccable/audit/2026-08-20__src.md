## Detailed Findings by Severity

### [P1] Form labels are not programmatically associated

- **Location:** 134 `<Label>` openings without `htmlFor` across 33 TSX files. High-density examples: `src/components/app/LancamentoAcoes.tsx` (13), `src/routes/_authenticated/tesouraria/recibos.tsx` (12), `src/components/app/RecebimentoAvulso.tsx` (8), `src/routes/_authenticated/biblioteca/index.tsx` (7), `src/routes/_authenticated/tesouraria/contas-pagar.tsx` (7).
- **Verified examples:** `LancamentoAcoes.tsx:119-143`, `RecebimentoAvulso.tsx:82-108`, `administracao/email.tsx:123-165`, `tesouraria/recibos.tsx:499-617`.
- **Category:** Accessibility
- **Impact:** screen-reader users encounter unnamed or ambiguously named inputs/selects; clicking the visible label does not focus the control.
- **WCAG:** 1.3.1 Info and Relationships; 3.3.2 Labels or Instructions; 4.1.2 Name, Role, Value.
- **Recommendation:** add stable `id` values and matching `htmlFor`; for Radix `Select`, place the `id` on `SelectTrigger`; reserve unbound labels only for true groups and use `fieldset`/`legend` or `aria-labelledby` there.
- **Suggested command:** `$impeccable harden`

### [P1] Destructive icon-only actions can be unnamed

- **Location:** `src/routes/_authenticated/tesouraria/contas.tsx:390-392`; audit similar icon-only triggers in recurring and table-value screens.
- **Category:** Accessibility
- **Impact:** the PIX delete trigger exposes only a trash icon, with no accessible name; assistive technology cannot determine the action before activating it.
- **WCAG:** 2.5.3 Label in Name; 4.1.2 Name, Role, Value.
- **Recommendation:** add contextual `aria-label` (for example, `Excluir chave PIX ...`) and retain the visible confirmation dialog.
- **Suggested command:** `$impeccable harden`

### [P2] Motion has no reduced-motion alternative

- **Location:** shared overlays and primitives in `src/components/ui/dialog.tsx`, `sheet.tsx`, `dropdown-menu.tsx`, `popover.tsx`, `skeleton.tsx`, plus accordion/navigation transitions. No `prefers-reduced-motion` implementation was found.
- **Category:** Accessibility / Performance
- **Impact:** users who request less motion still receive zoom, slide, fade, accordion and pulse animations.
- **WCAG:** 2.3.3 Animation from Interactions (AAA); user preference best practice.
- **Recommendation:** provide an intentional reduced-motion variant that removes translation/zoom and pulse while preserving visible state changes; do not use a global `0.01ms` kill switch.
- **Suggested command:** `$impeccable animate`

### [P2] Repeated touch targets below the 44×44 px design target

- **Location:** `AppShell.tsx:760` (28×28), `RichTextEditor.tsx:37` (28×28), `tesouraria/contas.tsx:390` (32×32), `tesouraria/tabela-valores.tsx:310` (32×32), `tesouraria/recorrentes.tsx:357` (32×32), carousel controls (32×32).
- **Category:** Responsive Design / Accessibility
- **Impact:** small mobile targets increase mistaps, especially for dense financial actions and users with motor impairments.
- **Standard:** WCAG 2.5.8 minimum 24×24 is generally met by 28/32 px controls, but the project's mobile quality target of 44×44 is not.
- **Recommendation:** enlarge the interactive hit area to at least 44×44 on touch layouts while keeping the icon visually compact.
- **Suggested command:** `$impeccable adapt`

### [P2] Production chunks remain heavy

- **Location:** build output: `index-*.js` 357.20 kB (105.30 kB gzip), `RichTextEditor-*.js` 330.83 kB (104.52 kB gzip), `AppShell-*.js` 118.28 kB (37.13 kB gzip), CSS 107.85 kB (18.11 kB gzip).
- **Category:** Performance
- **Impact:** initial or feature-entry download and parse cost can be noticeable on slower mobile devices; the editor chunk is especially expensive for a single capability.
- **Recommendation:** inspect chunk composition; lazy-load Tiptap/editor features only when editing is opened; verify whether the 357 kB index chunk includes utilities that can move behind server boundaries or dynamic imports.
- **Suggested command:** `$impeccable optimize`

### [P2] Browser build externalizes Node modules from an application backend file

- **Location:** build warnings for `node:fs`, `node:url`, and `node:path` imported by `src/lib/backend/importacao-pdf-sessoes.ts`; ineffective dynamic import of `src/lib/backend/db.ts` also reported.
- **Category:** Performance / Implementation Integrity
- **Impact:** current build succeeds, but an accidental client-side path to these modules can fail at runtime; ineffective dynamic import prevents the intended chunk boundary.
- **Recommendation:** verify server-only boundaries for PDF import and database modules; replace mixed client/server imports with explicit server-function entry points.
- **Suggested command:** `$impeccable optimize`

### [P2] ESLint baseline is unusable because line endings dominate every result

- **Location:** 54,130 `prettier/prettier` errors across 241 files; 0 non-Prettier errors in the JSON result.
- **Category:** Implementation Integrity
- **Impact:** CI and local lint cannot distinguish real defects from CRLF noise, reducing confidence in every change.
- **Recommendation:** align `.prettierrc`, `.gitattributes`, editor settings and Windows checkout policy; normalize line endings in a dedicated mechanical change, then rerun lint.
- **Suggested command:** `$impeccable harden`

### [P3] Status colors bypass semantic tokens

- **Location:** examples include `FaturaCard.tsx:87`, `usuarios/index.tsx:401`, `admin-saas/lojas.tsx:261-372`, `dashboard.tsx:181`, `painel/dados.tsx:170-184`, `painel/index.tsx:232,286-287`, `tesouraria/conciliacao.tsx:467-768`.
- **Category:** Theming
- **Impact:** direct amber/green/red/blue utilities make contrast and brand adjustments harder and can drift between screens despite existing dark variants.
- **Recommendation:** introduce semantic success/warning/info/danger tokens with light/dark values and migrate repeated states; preserve official Google/Facebook SVG brand colors as intentional exceptions.
- **Suggested command:** `$impeccable colorize`

### [P3] Standalone receipt HTML lacks document-level accessibility and token consistency

- **Location:** `src/routes/_authenticated/tesouraria/recibos.tsx:394`.
- **Category:** Accessibility / Theming / Implementation Integrity
- **Impact:** generated receipt markup has no `lang`, logo `alt` text or viewport metadata; Arial and hard-coded colors diverge from the app system. This mainly affects screen reading of the print preview, not the printed paper.
- **Recommendation:** add `lang="pt-BR"`, `meta charset`, viewport, meaningful/decorative alt handling, and shared print tokens; keep print-safe fallbacks.
- **Suggested command:** `$impeccable harden`

## Patterns & Systemic Issues

1. **Form accessibility is inconsistent by generation/feature area.** Newer screens such as authentication, calendar, reconciliation and several treasury dialogs use `id`/`htmlFor`; older or newly expanded modules still repeat bare labels.
2. **Compact icon controls recur in dense administrative tables.** The pattern needs a shared accessible icon-button contract rather than per-screen fixes.
3. **The token system is strong for surfaces but incomplete for statuses.** Repeated palette utilities are effectively an undocumented second color system.
4. **Quality tooling is present but obscured by line-ending policy.** Build succeeds and detector output is small; lint cannot currently provide a useful gate.
