## Dimension 1 — Accessibility · 2/4

**Evidence for score:**

Positives:

- `aria-label="Símbolo da loja"` on auth ⚜ div (`auth.tsx`)
- Sidebar section label opacity raised to `/65` (previously `/40`, inadequate contrast)
- `<Checkbox id="pago">` + `<Label htmlFor="pago">` correctly paired in `LancamentoDialog`
- shadcn/ui components (Dialog, Select, AlertDialog) carry correct ARIA roles from Radix

Issues found:

- **`contas.tsx:316`** — native `<input type="checkbox">` used for "Principal" toggle in `ChavesPixPanel`. No `id`; the `<Label htmlFor={...}>` references it by id pattern but the input is a raw element, inconsistent with the app's component system.
- **`tesouraria/index.tsx:344–429`** — `LancamentoDialog`: 6 of 8 `<Label>` elements have no `htmlFor`; corresponding `<Input>` and `<Select>` have no matching `id`. Labels are decorative only — screen readers cannot programmatically associate them.
- **`tesouraria/index.tsx:479–529`** — `TransferenciaDialog`: same pattern, 5 `<Label>` without `htmlFor`.
- **`tesouraria/contas.tsx:146–153`** — `<Button variant="ghost">` expand/collapse has icon only, no `aria-label` (e.g., `aria-label="Expandir Pix da conta"`).
- **`tesouraria/contas.tsx:132`** — `<TableHead></TableHead>` (expand column) is empty with no `aria-label`.
- **`tesouraria/conciliacao.tsx:193`** — item selection `<button>` elements rely on visible text, which is good, but the selected state is communicated only via `bg-muted` class — no `aria-pressed` or `aria-selected`.
- No `aria-live` or `aria-busy` on any loading state; but Sonner toasts are handled by the library.

## Dimension 2 — Performance · 3/4

**Evidence for score:**

Positives:

- TanStack Query handles all data fetching with proper caching and deduplication
- Build output: 1.31 s — no bloat
- Lucide icons are tree-shaken per-import (no icon barrel import)
- `animate-spin` used only on `<Loader2>` during async ops (5 locations) — correct
- `animate-pulse` used only in `<Skeleton>` — correct
- `enabled: !!irmaoId && isDesktop` in `painel/index.tsx:66` prevents unnecessary fetches on mobile
- No `will-change` or `transform-gpu` misuse found

Issues found:

- **No route-level code splitting.** TanStack Router supports `lazy()` routes; all routes (`/irmaos`, `/tesouraria`, `/contabilidade`, etc.) are bundled together. For a management SPA this scale is acceptable today, but the bundle grows linearly with every new page.
- **`conciliacao.tsx:123–128`** — OFX and system lists are filtered client-side with `.filter()` on full arrays; no pagination on the scrollable lists. If an OFX file has hundreds of lines, the DOM grows unbounded. Low risk today, but no ceiling.
- **No virtualization** on long `lancamentos` tables. At scale (>500 rows), scrolling performance degrades.

## Dimension 4 — Responsive Design · 3/4

**Evidence for score:**

Positives:

- Financial tables wrapped in `overflow-x-auto`: `tesouraria/index.tsx`, `movimentos.tsx`, `contas.tsx` (outer + ChavesPixPanel inner), `irmaos/$id.tsx`
- Action bar in `conciliacao.tsx:249` uses `flex-wrap gap-3` — wraps correctly on narrow widths
- `MetricCard` hardened: `min-w-0`, `truncate` on hint, `shrink-0` on icon
- PainelShell constrains to `max-w-md` on mobile
- AppShell sidebar collapses; `useIsDesktop` gates heavy queries on mobile

Issues found:

- **`painel/index.tsx:227`** — TILES grid is `grid-cols-4` but has **5 items**. The 5th tile (Comunicações) wraps to a second row and appears alone at 1/4 width, misaligned left. Fix: `grid-cols-4 has-[*:nth-child(5)]:grid-cols-5` or simply `grid-cols-5` (tiles shrink to fit).
- **`tesouraria/index.tsx` — `hidden sm:table-cell`** columns (Competência, Conta). On mobile (< 640 px), these columns vanish entirely with no expandable row or detail fallback. Data loss: users cannot see competência or account on small screens.
- **`contas.tsx` ChavesPixPanel form** — `md:grid-cols-6` renders as single-column on mobile. Acceptable, but the `<Button size="sm">Adicionar</Button>` has no `w-full` on mobile, leaving it left-aligned in a tight layout.
